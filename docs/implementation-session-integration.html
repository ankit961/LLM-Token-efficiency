Implementation & Session Integration

How the runtime attaches to a Claude Code session, what fires on each tool call, and where the token savings actually come from — grounded in what the client can really do.

The load-bearing facts. You install once — a local daemon, an MCP server, and a hook block in settings.json; every subsequent Claude Code session then auto-wires itself with no API key and no manual connection. Per-session state (the context-object graph, manifest, and ledger) is created on session start; the expensive index (repo symbols, content-hash store) is shared across sessions. The graph lives in the runtime — the model only ever sees changed tool-result bodies and MCP results, never the graph. And one honest boundary up front: on a subscription the runtime can shrink accumulated tool-result occupancy and avoid fat reads — it cannot shrink the fixed base prefix (system prompt, tool definitions, CLAUDE.md) or control eviction and TTL. Those require owning request assembly, which is gateway mode.

1Session attachment

ContextRuntime does not “connect to” a session in any interactive sense. Installation writes hook entries and an MCP server registration; from then on Claude Code invokes the hooks and opens the MCP connection itself, per session.

Shared across all sessions (the daemon)Per-session state
Repo symbol index (tree-sitter / LSP), content-hash blob store (CAS), deferred code graphContext-object graph, manifest, token ledger, cache-island estimate, task capsule

Keying. The SessionStart hook receives the session id and cwd and provisions per-session state. verify MCP tool calls do not carry Claude Code’s session_id, so the MCP path cannot be keyed from it — the daemon keys MCP calls by cwd plus a short-lived session token the SessionStart hook injects (falling back to cwd+process ancestry). Concurrent sessions on one repo share the index but keep isolated graphs; worktrees and branches key on repo + worktree + commit.

Boundaries handled explicitly. SessionStart fires with source ∈ {startup, resume, fork, compact} — the capsule is seeded on all of the last three, not just compaction. Task-tool subagents run on their own sidechain with their own token usage; the ledger attributes them separately (via agent_id/agent_type on the hook input) so they don’t distort main-thread totals.

2Hook wiring — and the real admission mechanism

Correction from integration review. The intuitive design — “PreToolUse redirects an oversized Read into read_symbol” — is not a real capability. PreToolUse can only return allow / deny / ask with a reason; it cannot change the tool name, substitute a tool, or (for Read) even inject limit/offset. So admission control is delivered primarily on the output side, not the input side.

The reliable lever is PostToolUse output reduction. The read or command runs; the hook then replaces the body the model sees with a reduced/semantic version plus a handle. This works regardless of model cooperation and leaves no denied-attempt residue in the prefix.

  • verify Version-gated. Output replacement for built-in tools (Read/Bash/Grep) shipped later than the MCP-output equivalent. The runtime asserts a minimum Claude Code version, detects the capability at SessionStart, and degrades loudly (“native reduction unavailable — MCP-only mode”) rather than silently no-op.
  • Synchronous & schema-perfect. Replacement only happens on the synchronous decision path, so the reducer sits on the critical path of every fat tool call (budget: CAS write + compress + dedup lookup, not just a socket hop). A malformed replacement produces “tool_use ids without tool_result” errors that abort the turn — the reducer must preserve the exact structured response shape (Bash → {stdout,stderr,exitCode}, Read → file-content object) and is validated before emit.
  • verify Payload may be pre-truncated. Claude Code truncates very large outputs to a disk-file reference before the hook sees them, so for the fattest results the hook may not receive the full bytes. Content-hashing / dedup is computed over what is actually received, and retention is verified empirically at 50 KB / 500 KB / 5 MB.
  • Retention heuristic. PostToolUse fires once, at read time; there is no later “downgrade” hook and no retain_turns. Reducing a file the agent is about to edit forces an under-context re-read next turn — self-inflicting the very rewrite amplification we measured. Rule: never reduce a Read whose path is a likely edit target; reduce logs, tests, and large greps aggressively.

What PreToolUse is actually for. Observation and steering, not redirection. In advisory mode it records large reads/bypasses and attaches a warning; in enforced mode it may deny an oversized read with a reason pointing at read_symbol — used sparingly, because the denied attempt and its reason become resident prefix, and hard-denying a read the agent needs breaks the Edit read-before-edit invariant. For Bash the hook can rewrite command (a genuinely stronger lever than for Read), but rewriting a user’s explicit shell command risks breaking legitimate work, so it stays best-effort.

best-effort The Bash escape hatch narrows; it does not close. Read/Edit permission rules don’t cover Bash, so a shell classifier is the only lever — and it is an unbounded parsing problem. cat/sed/head/tail are easy; awk/perl/jq/xxd/od/python -c 'open(...)'/find -exec cat, pipes, $(...) and heredocs are all readers that will slip through. The honest claim is “narrowing of the most common materializers,” and the Bypass-Rate metric counts any file-materializing command as a native read.

# settings.json (shape)
"hooks": {
  "SessionStart":  [{ "command": "crt hook session-start" }],   # provision state, inject session token, seed capsule
  "PreToolUse":    [{ "matcher": "Read|Grep|Glob|Bash|mcp__crt__*",
                      "command": "crt hook pre"  }],             # observe / warn / (enforce) deny+steer
  "PostToolUse":   [{ "matcher": "Read|Grep|Bash",
                      "command": "crt hook post" }],             # the real lever: reduce output + handle
  "PreCompact":    [{ "command": "crt hook pre-compact"  }],
  "Stop":          [{ "command": "crt hook stop" }]              # finalize capsule, flush ledger
}

3MCP tool surface

A small model-facing surface (six to eight tools) hides the language servers, search, and blob store behind it. Semantic reads are where enforced savings become positive rather than merely punitive, because the model gets a usable small slice instead of a denied read.

Handles & the manifest. Fat payloads return a result:// / context:// handle that resolves against the CAS; every delivery is recorded in the manifest so an already-resident object comes back as a reference (dedup) and a changed one as a delta. MCP output can be replaced via the MCP-output hook (which shipped earlier than the built-in one).

The envelope is itself prefix tax. Every response carries ids@hash, tokens_estimated, manifest_delta, expandable, raw_handle — and each of those lands in a tool_result that is re-billed every subsequent turn. The envelope is budgeted: default/empty fields are omitted and manifest_delta stays terse. Two more: a Grep token estimate is speculative before the search runs, so oversized search output is bounded by post-hoc reduction, not a pre-emptive deny; and an expired result:// handle returns a typed “expired — re-materialize” signal, never a silent empty that makes the model loop.

4Daemon & state

One local daemon holds a SQLite store (node/edge adjacency plus a content-addressed blob store for raw payloads behind handles) and the shared repo index, rebuilt incrementally on file-watch at machine cost — zero model tokens. Hooks and the MCP server talk to it over a unix socket with a tight client deadline (see §5).

What the ledger can and can’t measure. verify The load-bearing source is the local JSONL transcript, deduplicated by requestId. OpenTelemetry is opt-in — it only reaches the daemon if the user configures Claude Code’s OTLP exporter to point at it. The 5h/7d rate-limit percentages are not programmatically pollable out-of-band; the only supported way to read them is for the daemon to be the statusLine command. Both are labeled “requires user config,” and neither is assumed present.

Cache-island state is inference, not reconstruction. verify The real cache key is the exact prefix bytes (system prompt + tool schemas + CLAUDE.md + history), which the JSONL does not expose. So cache_creation ≫ cache_read ⇒ rebuild is a heuristic that cannot be cleanly separated from a normal large new turn, and the 1-hour TTL is itself unverified from the client (public docs describe a 5-minute default with an optional 1-hour extension). Every cache-island, BROKE, and TTL figure is therefore an estimate that drives batching/pressure hints — never reported as a measured occupancy number, and the batching window is calibrated per account rather than hardcoded.

Response bodies are canonicalized to a stable shape before hashing, so dedup and SUPERSEDES stay stable across the structured (Bash) and file-object (Read) forms.

5Lifecycle, failure & security

  • Crash / restart recovery. The capsule is built continuously from tool events and git state, so it never depends on a departing model summarizing itself — a crashed or rate-limited session resumes from the last checkpoint.
  • Fail-open, time-bounded. Every shim carries a ~100–200 ms client deadline; a dead or hung daemon, a socket error, or a timeout returns allow/no-op so the agent never freezes. Enforcement that can’t reach the daemon degrades to passthrough, loudly, not silently.
  • Provenance & injection boundary. Every object carries a trust level (user / source / test / tool / model-inference / external). External content is data and is never promoted to instruction — the guard that keeps a poisoned doc or tool result from steering the agent, and that keeps a capsule from shipping one model’s hallucination to the next as fact.
  • Secrets & locality. Secrets are redacted before any content is materialized into context. All transcripts and content stay on the machine; OTel content export remains opt-in. Enterprise adds tenant/workspace separation and an ACL check before any cross-context transfer.
