## 2. Two real product bugs found + fixed this session (permanent, ship regardless of experiment outcomes)

1. **MCP cross-repo startup failure** (commit `0370b85`) — the MCP server subprocess couldn't
   import `contextruntime` when spawned with `cwd` set to a *different* repo's worktree (the agent
   works in a target repo like django, not this package's own root; `python3 -m contextruntime.cli`
   only resolves via the interpreter's cwd-adds-to-sys.path trick, since `contextruntime` is not
   pip-installed). Fixed via explicit `PYTHONPATH` in the generated MCP config
   (`ClaudeBackend._mcp_config_path` in `contextruntime/corpusrunner.py`).
2. **Ambiguity-hint budget blowout** (commit `30feb00`) — a real django symbol with several
   commonly-named references (`get`/`set`/`deconstruct`/`compile`) returned 99% overhead and
   `budget_insufficient=true` because the candidate-list dump for ambiguous names had no cap. Fixed
   by capping shown candidates at 5 (`contextruntime/codegraph/bundle.py`,
   `AMBIGUITY_HINT_CAP`), honest "+N more" in the rendered text.

Both are verified via direct reproduction (broken-then-fixed on the exact case that exposed them),
not guessed. **Lesson for future work in this codebase**: a mechanism that "works" in isolated
manual testing (interactive shell, repo-root cwd) can silently fail in real batch/automation
context (foreign cwd, no interactive terminal) — verify integration points under the SAME
environment the real automation uses.

## 4. Using a different account — what actually changes

- **Claude Code auth**: re-run whatever your environment uses to log into the new account (this
  session hit a subscription session-window limit, not an API-key/billing issue — a different
  account gets its own independent window).
- **`gh` auth**: independent of the Claude account; check `gh auth status` — if it's a different
  *person's* GitHub identity (not just a different Claude subscription), commits will attribute
  differently. If it's the same GitHub identity with just a different Claude login, no change needed.
- **This repo's git remote / local files**: unaffected — same machine, same filesystem, same clone.
- **Session memory**: this assistant's auto-memory system is keyed by project directory path, not
  by account — a new session in this same directory may or may not have continuity depending on
  environment specifics. Don't rely on it; this document is written to not require it.
- **Empirical quota anchor** (real data, not estimated): one subscription session window fit
  **~24–25 real SWE-bench-scale Claude Code task runs** (~900s budget each) before hitting the
  limit. Use this to size any future batch, not a token estimate — headless `claude -p` here never
  exposed token-level usage stats.

## 6. Process norms established this session (worth preserving)

- **Validate small before committing quota to a large batch**, with an explicit hard gate (not
  just "did it run without erroring" — check the actual signal, e.g. `semantic_reads > 0`, not just
  `termination_reason == "completed"`).
- **Check in before spending meaningful quota** — this user consistently wants a checkpoint before
  a batch that costs real subscription usage, even mid-investigation.
- **Never silently reclassify uncertain data as favorable** — the classifier's own "never
  manufacture exploration/reducibility" conservatism was deliberately preserved in the opportunity-
  ceiling analysis; don't loosen it to make a number look better.
- **Privacy sweep before every commit**: `git grep -nEi 'skilink|InfyU|/Users/ankit|journeyController|emailCampaign'`
  over changed files — this is a standing project rule, not session-specific.
- **Avoid backticks inside `git commit -m "..."` strings** — zsh interprets them as command
  substitution even inside double quotes; harmless but sloppy (silently strips the quoted word).
- Frozen artifacts get new versioned documents on change, never silent edits — this repo's house
  style throughout (`corpus-plan-v1` → `v2` → `v2.1`; the steering `v1` → `v2` addendum; this
  handover itself, dated, rather than overwriting a prior status doc).
