CONTEXTRUNTIME  ·  SEMANTIC I/O FOR CODING AGENTS

Coding agents pay for the same context again and again.

Agentic coding is a loop. Every request re-sends the entire conversation, so a token you admit once is re-billed on every later turn. The real unit of cost isn’t the token — it’s the token-turn. ContextRuntime controls what becomes context, at what resolution, and for how long.

measured: 168 sessions · ~170k requests 96% of context = cache re-reads 82% of cache-writes = prefix rebuilds
The problem

The loop multiplier

A coding agent doesn’t send one message and get one answer. It runs a loop: read a file, run a test, edit, re-run — dozens to hundreds of model requests per task. And on every request the whole conversation so far is sent again as the prompt prefix.

So the cost of admitting something into context is not paid once. A 5,000-token file opened at turn 10 of a 60-turn session sits in the prefix for the next 50 requests and is billed on each. That’s the mechanism that makes long agent sessions expensive — and it’s invisible if you only count the first read.

How agents spend tokens today

Every request ships the whole prefix

Claude Code, Codex and Cursor all assemble the same shape of request: a system prompt, the tool definitions, your rules (CLAUDE.md / AGENTS.md), the entire conversation so far, every prior tool result, and the one new message. Prompt caching makes re-reading the stable part cheap — an exact-prefix, per-model cache — but cheap is not small: cached tokens still occupy the window and still get processed on a break.

Native habits make the prefix grow fast: whole-file reads to find one function, raw grep dumps, thousands of lines of passing-test output. All of it lands in the prefix and rides along for the rest of the session.

Why the bill balloons

The cache keeps breaking — and rebuilding the whole prefix

Prompt caching only helps while the prefix stays warm. The cache is exact-prefix and per-model with a one-hour TTL on subscriptions, so it breaks whenever you step away past the TTL, switch models, hit a compaction, reconnect an MCP server, or upgrade the client. On a break, the entire prefix — often hundreds of thousands of tokens — is re-processed and re-cached from scratch.

Across the measured corpus, 82% of all cache-write tokens are these rebuilds, not new content. That’s the single largest pool nobody was looking at.

What we propose

A semantic I/O layer between the agent and everything expensive

ContextRuntime sits at the boundary the tokens actually cross. It reads the repository, runs the tests, and talks to tools at machine cost — then decides what becomes model context and at what resolution. Raw source, logs, and search results stay outside the window until the task proves it needs them.

It ships in three modes of increasing control, so it can start on a plain subscription with no API key — driving Claude Code’s hooks and MCP — and grow into a full gateway for enterprise.

MODE 1

Advisory MCP

Semantic tools offered alongside native ones. Fast install; savings depend on the agent choosing them.

MODE 2

Enforced adapter

Hooks gate reads and reduce tool output before the model sees it. Admission control on a plain subscription — no API key.

MODE 3

Full gateway

Owns request assembly, eviction and lifecycle. Unlocks the pools admission alone can’t reach. Enterprise core.

How it reduces tokens

Four levers, each shrinking what becomes prefix

None of these compress the model’s prompt after the fact. They change what enters the window in the first place — which is what compounds across the loop.

ContextReduce

ships first

SemanticFS / Admission

highest ceiling

cheap · safe

The capsule

carry state, not transcript

Resume a task from ~2k of structured state — intent, verified facts, repo refs — instead of dragging the whole transcript into a new session or model.

700k transcript → 2k capsule
Why it works

One variable moves both pools: prefix size

The two big costs look separate — the prefix re-read on every warm turn, and the prefix rebuilt on every break — but they share a multiplier. Shrink the prefix and the resident re-reads get cheaper and every unavoidable rebuild gets cheaper, at once. You can’t stop someone stepping away for an hour, but you can decide how large the thing is that gets rebuilt when they come back.

Honest scope. These are design-partner measurements from one corpus, not a market benchmark. The headline savings claims use only provable pools; illustrative examples are marked. The decisive experiments are still ahead: can admission shrink the prefix without hurting task success, and can a 2k capsule replace a 700k transcript. The roadmap gates on those two answers before anything scales.
