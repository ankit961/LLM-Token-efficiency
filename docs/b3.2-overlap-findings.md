## The two halves of "overlap"

Native `/compact` is a **blunt, lossy reset**: at the context limit it evicts the *entire* prefix
(dead and live objects) into a summary. B3 is a **surgical, lossless trickle**: it retires only
provably-dead/safe objects, continuously. That difference splits the overlap into two measurable
effects:

- **REDUNDANCY** (Model B, on real reset boundaries): once native resets at boundary K, everything B3
  would have retired before K is gone anyway. B3's *unique* token-turn saving is only what it retires
  inside each inter-reset window before that window's reset.
- **DEFERRAL** (Model A, parametric over a context threshold θ): B3 removing dead weight keeps the
  resident prefix smaller, so it crosses θ *later* — or never. Every avoided/deferred crossing is a
  lossy summarization B3 replaces with lossless retirement — the value native cannot provide (native
  *is* the thing being deferred). Measured on the real pre-crossing trajectory; no post-reset modelling.

Retirement policy = B3.1's safe realizable set (superseded at obsolescence; safe tails at
`tail_turn + 5`).

## Setup facts

The 60 django sessions peak at **cache_read p50 = 80k, max = 149k** — all below the real ~190k context
limit, so native `/compact` **never fired** (they are genuinely single-window). The giant session is
the only real multi-window trace: **20 detected reset boundaries** (cache_read repeatedly builds then
drops to a ~32k summary baseline).

Crucially, **tool-output objects are only ~16% of the peak resident prefix** (range 8.6–23%). The other
~84% — conversation, system prompt, tool definitions — B3 cannot touch. So B3's peak-reduction power is
structurally **capped near that object share**.

## Model A — Deferral (parametric θ)

Mean peak-resident reduction from B3 = **14.97%** (it retires nearly the whole ~16% object slice by the
peak turn). Among sessions that *would* compact at threshold θ:

| θ (context limit) | n would-compact | fully avoided | mean deferral (turns) |
|---:|---:|---:|---:|
| 80k | 30 | **30%** | 24.7 |
| 120k | 10 | **100%** | 24.0 |
| 160k | 0 | — | — |
| 190k (real) | 0 | — | — |

Reading: at a 120k limit, B3's ~15% peak shave keeps **all 10** would-compact sessions under the line —
it *avoids the lossy compaction entirely*. At a tighter 80k limit it avoids 30% and defers the rest by
~25 turns. At the real ~190k limit these sessions never reach the threshold at all.

## Model B — Redundancy (giant, 20 real resets)

On the heavily-compacting giant session, B3's **unique** token-turn saving is only **8.4% of its
standalone** saving (peak reduction 9.4%). Native `/compact` already evicts ~92% of what B3 would
have saved — so B3's standalone 18–20% on that session is a **mirage**; the marginal is ~1.5%.

## Synthesis — the overlap, precisely

B3's value is **regime-dependent**, and the raw-token headline only holds in one regime:

- **Single-window (the real ≤190k regime, all 60 django sessions):** native compaction never fires, so
  B3 is **purely additive** — its ~8–11% safe NET (B3.1) stands unopposed. This is a real, lossless,
  direct token/cost saving.
- **Multi-window (heavy compaction, the giant):** the raw token saving is **~90% redundant** with
  native `/compact` (unique ≈ 8% of standalone ≈ ~1.5% absolute). B3 is **not** a raw token-saver here
  — native already does it.

But B3 adds one thing native cannot, in *both* regimes near the threshold:

- **Compaction deferral / avoidance.** By shaving ~15% (its object slice) off the peak, B3 defers or
  entirely avoids the *lossy* native summarization — keeping the full, un-summarized context alive
  longer. At a 120k budget it avoided compaction outright for every would-compact session. That is a
  **fidelity** win (less lossy summarization, fewer forced re-reads), not a raw-token win.

## Verdict — the offline picture is now complete

The native-compaction overlap does **not** erase B3, but it **relocates** its value:

1. **As a raw token/cost saver, B3 is real only in the single-window regime** — ~8–11% safe, additive,
   lossless. On multi-window sessions native `/compact` captures ~90% of it; B3's marginal there is
   low-single-digit.
2. **As a context-lifecycle mechanism, B3's unique value is compaction deferral/avoidance** — a ~15%
   peak shave that keeps sessions lossless-longer, capped by the ~16% tool-output share of the prefix.

So the honest positioning: B3 is **not** the 25–40% whole-session token lever the program originally
chased — native compaction already occupies the multi-window territory where those numbers would live.
It **is** a genuine, safe, ~8–11% additive saver on the common single-window session, plus a lossless
alternative that defers native compaction near the limit. Whether that combined value justifies a
history-rewriting transformer is now a **product/fidelity** judgement, not an open measurement — every
offline lever has been quantified.

## Caveats

- **θ-sweep is a what-if** on real single-window trajectories; it models the regime these sessions
  would enter if the limit were lower, it does not re-model the post-reset trajectory (Model A only
  needs the pre-crossing part, which is real).
- **Redundancy is n=1** (the giant, a messy trace whose cache_read reaches ~1M — likely a 1M-context or
  multi-call session); its 8.4% unique fraction is indicative, not a corpus constant.
- **Object share (~16%) is the hard cap** on peak reduction; a bigger deferral would require
  summarizing conversation, which is exactly native `/compact`'s (lossy) job.
- No live run; the token-turn savings remain counterfactual. Frozen B1, B2 artifacts, and the G1/G2
  closure were not touched.
